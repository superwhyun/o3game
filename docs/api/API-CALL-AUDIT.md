# 클라이언트 API 호출 점검 (2026-10-09)

범위: 웹 클라이언트 자동 갱신, 소켓 알림 이후 재조회, 관리자 화면 이벤트, 건설 완료 재시도, AI 워커. 아래 수치는 한 브라우저 탭의 로그인/화면 진입이 끝난 뒤, 조작이나 완료 이벤트가 없는 1분을 기준으로 합니다. 이전 수치는 호출 경로와 주기로 계산한 값이며, 수정 후 수치는 Playwright에서 시간을 이동시키며 HTTP 요청 수를 검증한 값입니다. 실사용 서버의 트래픽 측정값은 아닙니다.

| 화면 | 수정 전 자동 요청/분 (약) | 수정 후 자동 요청/분 |
| --- | ---: | ---: |
| 성계도, 행성 선택 상태 | 32 | 17 |
| 함대 편성 / 함대 운용, 정찰 패널 닫힘 | 24 | 5 |

성계도 17회: 사용자 상태 4, 이동 경로 4, 성계 정보 2, 전투기록 1, 정찰 전체기록 2, 선택 행성 정찰기록 2, 침입 탐지 2. 함대 화면 5회: 사용자 상태 4, 전투기록 1. 일반 화면은 상태 30초, 전투기록 60초 주기입니다. 관리자 통계는 대시보드가 보일 때만 갱신합니다. 정찰기록 화면은 30초마다 전체기록·침입 탐지를 조회합니다.

## 확인 및 수정

- 함대 편성 조회와 `/api/auth/me`가 같은 전체 상태를 반환하는데 각각 조회했습니다. 자원/함대/재진입/포커스 갱신이 하나의 사용자 상태 조회와 적용 작업을 공유하도록 했습니다. 군사 화면 상태는 15초, 일반 화면은 30초마다 조회하며 이미 충분히 최근인 상태는 다시 조회하지 않습니다.
- 전투기록은 자동 갱신을 60초로 제한했습니다. 정찰기록은 화면에 필요한 경우 30초마다 조회합니다. 소켓 변경 알림과 명시적 새로고침은 최신 정보를 요청합니다. 소켓/포커스/타이머가 겹치는 군사 갱신은 3초 안에 한 묶음으로 합칩니다.
- 정찰기록 좌표 이동의 중복 성계 조회, 동일 행성 선택의 정찰 재조회, 동시 GET 요청은 제거/공유했습니다. 일반 성계도 자동 갱신은 30초, 이동 경로는 15초입니다.
- 건설 완료 확인 실패를 매초 재시도하는 경로를 발견했습니다. 5초부터 최대 60초까지 간격을 늘리며, 429의 서버 대기시간도 준수합니다. 숨겨진 탭에서는 완료 확인 요청을 보내지 않습니다. 카운트다운/자원 예상 표시/3D 갱신은 로컬 계산입니다.
- 관리본부를 다시 열 때마다 이벤트 리스너가 추가되어 클릭 1회에 여러 요청이 생길 수 있었습니다. 이벤트 등록을 1회로 제한하고 불필요한 초기 통계 조회를 제거했습니다.
- 관리자 API도 공통 API 클라이언트를 사용하여 동시 GET 중복 방지와 Retry-After 대기를 공유합니다. 쓰기 요청을 자동 재전송하지 않습니다.

## AI 워커

- 대기 중 claim 조회는 3초 간격, heartbeat는 10초 간격이므로 워커 제어 요청은 대략 분당 26회입니다. 작업 실행 시 decide/complete 요청이 추가됩니다. 이 경로는 별도의 워커 제한(분당 600회)을 사용합니다.
- 봇은 한 판단에 사용자 상태·카탈로그·성계·정찰기록 4회 조회, 액션 직전 상태 재확인 1회와 최대 1회 게임 액션을 실행합니다. 기본 판단 간격은 60초이고 봇 사용자별 제한을 적용하므로 사람 사용자의 분당 120회 한도를 소모하지 않습니다. 개선 제안은 별도 6시간 간격으로 제한됩니다.
- 카탈로그 캐시나 워커 대기 간격 조정도 가능하지만 현재 봇별 호출량은 작습니다. 이번 수정은 화면 중복 조회와 실패 재시도에 집중했습니다.

## 검증과 범위

`ogame-3d/test/api-call-budget-ui.spec.js`에서 1분 성계도 17회, 함대 화면 5회, 완료 확인 실패 10초 동안 2회, 관리본부 반복 진입 후 속도 변경 1회에 요청 1회를 검증합니다. 초기 로그인, 사용자 액션, 작업 완료, 소켓 이벤트, 여러 탭을 함께 쓰는 경우에는 호출이 추가됩니다. 서버의 사용자별 분당 120회 제한은 유지합니다.
