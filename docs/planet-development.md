# 행성 개발과 생산 특성

행성의 전체 면적은 `floor((지름km / 800)^2)`칸으로 고정된다. 기본 가용률은 환경에 따라40~50%이며 테라포밍 연구마다2%p씩 증가하고100%에서 멈춘다. 건물 레벨1당1칸, 업그레이드 예약1회당1칸을 사용한다. 철거는 레벨을1 낮추고 완료 시1칸을 회수하며 자원 환급은 없다. 함대·방어 유닛·연구는 이 지상 건설 면적을 소비하지 않는다.

테라포밍은 플레이어 공통 기술이다. 연구소10, 에너지 기술12, 천체물리학4를 갖춘 행성에서 연구하며 모든 소유 행성에 적용된다. 일반 연구는 기존처럼 행성별이다. 테라포밍 최대30레벨이며 모든 행성이100%라면 추가 연구를 허용하지 않는다.

금속·크리스털 매장 보정은 광산 생산에만 적용하고 무료 기본 생산에는 적용하지 않는다. 평균 온도10°C가 중립이며1°C당0.2%씩 추운 행성의 중수소 생산과 따뜻한 행성의 태양광 발전에 유리하다. 모든 보정은0.8~1.2 범위다. 신규 모성은 영구 저장되는 온도·매장 특성을 부여하며 추운 환경40%, 고온 환경44%, 온화한 환경50%의 기본 가용률을 갖는다.

## DB와 데이터 전환

건설·철거·연구·유닛 생산·취소는 자원과 큐를 함께 변경하므로 MongoDB replica set이 필요하다. 기존 `docker-compose.fleets.yml`의 replica set 설정을 재사용한다. standalone에서는 해당 변경 요청을503으로 거부하고 로그인·상태 조회는 유지한다. 설정법은 [함대 개발 안내](fleet-development.md)를 참고한다.

운영 데이터 전환 전에는 백업을 남기고 아래 dry-run을 확인한다.

```sh
cd server
npm run migrate:areas
npm run migrate:areas -- --apply
```

기존 행성은 중립 매장 보정1.0을 사용하고 지름·온도·건물을 보존한다. 완료 건물과 예약을 수용하도록 기본 가용률만 최대100%까지 보정한다. 전체 면적보다 많이 사용한 예외는 보고하며 기존 시설을 삭제하지 않고 추가 건설을 차단한다. 접속 정산에서도 누락 메타데이터에 같은 보정을 적용한다. 도구는 재실행 가능하다.

동일 건물의 뒤쪽 업그레이드 예약이 있으면 뒤쪽부터 취소한다. 진행 중인 작업에 필요한 시설은 철거할 수 없다. 철거 예약으로 선행 조건이 사라지는 시설을 이용한 새 작업도 막는다. 저장고 철거로 저장 한도가 줄면 기존 자원 상한 정책에 따라 초과 자원이 줄어든다. UI는 명령 전에 예상 손실을 표시한다.

## 로컬 검증

```sh
npm test --prefix server
npm run build --prefix ogame-3d
node server/scripts/previewPlanetAreas.js
# 다른 터미널에서 (고정 포트3037,5178이 비어 있어야 한다)
PLANET_UI_FIXTURE_FILE=/tmp/oogame-planet-preview.json \
  ./ogame-3d/node_modules/.bin/playwright test --config ogame-3d/playwright.planets.config.js
```

새 통합 테스트와 프리뷰는 독립적인 임시 MongoDB를 생성한다. 첫 실행에는 테스트용 MongoDB 바이너리를 다운로드한다. 프리뷰를 종료하면 해당 임시 DB가 정리된다. 테스트 fixture는 테스트용 로그인 토큰을 포함하므로 공개하거나 커밋하지 않는다. 기존 함대·정찰·좌표·standalone 통합 테스트의 DB 환경 변수는 기존 문서에 따른다.
