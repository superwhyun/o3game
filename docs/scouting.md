# 성계도 정찰

성계도에서 다른 플레이어 행성이나 빈 궤도를 선택하고 `정찰 · 1척`을 누른다.
미리 건조한 미배정 정탐 드론을 클릭마다 1척씩 보낸다. 다른 함대에 예약한 함선은 사용할 수 없다.
출격은 독립 정찰 임무로 표시하며 저장된 함대 번호를 소비하지 않는다.

도착 전에는 정보를 제공하지 않는다. 도착 후 성계도 오른쪽에 최신 관측이 표시되고,
`정찰 기록` 또는 전투 화면의 `정찰 보고`에서 이력을 열 수 있다.
관측 시각을 표시하고 미확인 항목과 관측 결과 0을 구별한다. 예전 보고의 정보를 새 보고에 합치지 않는다.

## 정보와 귀환 규칙

출발 당시 첩보 기술 A와 도착 당시 목표 첩보 기술 D로 `clamp(1 + A - D, 1, 4)` 단계를 정한다.

| 단계 | 공개 정보 |
|---|---|
| 1 | 당시 점령자·행성 이름·자원 |
| 2 | 단계 1 + 주둔 함선 |
| 3 | 단계 2 + 방어시설 |
| 4 | 단계 3 + 건물·연구 |

빈 궤도에는 미점령 사실만 보고한다. 출격 후 점령 상태가 바뀌면 도착 당시 좌표를 기준으로 관측한다.
자기 소유가 됐다면 아군 보고를 남기고 귀환한다.

탐지 확률은 `clamp(50 + 15 × (D - A), 5, 95)%`다. 이동 ID와 서버 비밀 값으로 판정을 고정한다.
탐지됐으며 공격 가능한 군사 함선이나 방어시설이 있으면 격추된다. 민간 수송선은 요격하지 않는다.
수집 정보는 요격 전에 전송하므로 격추돼도 허용된 단계의 보고서는 받는다.
생존 정찰선은 실제 이동 시간에 따라 귀환해 원래 주둔 수량으로 돌아온다. 격추된 함선은 환급하지 않는다.
상대는 탐지된 침입의 정찰자·좌표·시각·요격 결과만 조회한다.

## 서버 계약

- `POST /api/game/scouts`: `{requestId, originPlanetId, destination: {galaxy, system, planet}}`. 성공 201에 이동과 스냅샷을 반환한다. 같은 요청 ID/주문은 같은 이동을 반환하며 다른 주문은 409다.
- `GET /api/game/fleet-requests/:requestId`: 본인 요청의 확정 결과를 복구한다.
- `GET /api/game/scout-reports`: 본인 보고 목록. 목적 좌표 필터, cursor, limit(기본 20, 최대 50)을 지원한다.
- `GET /api/game/scout-reports/:id`: 본인 상세. 타인의 보고서는 404다.
- `GET /api/game/scout-alerts`: 본인이 탐지한 침입의 제한된 알림 목록.

새 출격에는 MongoDB replica set이 필요하다. 조건이 안 맞으면 출격 전에 503을 반환하고 함선을 차감하지 않는다.
기존 standalone 로그인·건조 등은 유지한다. 환경 준비는 [fleet-development.md](fleet-development.md)를 참고한다.
보고서는 공개 가능한 sections만 저장한다. 임무당 보고 1개와 생존 수량 환급 1회를 트랜잭션과 고유 인덱스로 보장한다.

클라이언트는 클릭마다 고정된 요청 ID/출발지/좌표를 sessionStorage에 저장한다.
응답 유실 시 같은 요청을 조회·재시도하며 새 임무를 만들지 않는다.
자동 갱신은 출격 버튼 DOM을 유지해 연속 클릭을 보존하고, 소켓 알림과 보조 polling으로 보고를 복원한다.

## 검증

2026-10-05 서버 테스트 66개(실패/skip 0), Chrome E2E 6개, frontend build를 통과했다.
서버 검사는 별도 replica set 및 standalone 테스트 DB를 사용한다.
브라우저 검사는 별도 DB에서 건조→연속 출격→보고→귀환, 응답 유실, 빈 궤도, 모바일을 확인한다.
시간 단축은 격리 브라우저 DB에만 적용한다.

현재 실행 중인 로컬 서버를 실제 타이머로 확인하는 선택적 smoke:

```sh
node server/scripts/checkScoutsLive.js --allow-live
```

스크립트는 `server/.env`의 DB와 localhost:3000 서버를 사용한다. 원래 계정은 수정하지 않는다.
임시 계정 2개와 정찰선 3척으로 로그인·출격·실제 도착/귀환·보고·수량 복구를 확인하고,
생성한 계정 ID의 임무·보고·큐·계정만 정리한다. 서버 실행 주소는 `SCOUT_CHECK_BASE_URL`로 지정한다.
현재 실제 DB/서버에서도 이 검사를 통과했다. 원격 배포 및 물리 모바일 Safari는 검증하지 않았다.
