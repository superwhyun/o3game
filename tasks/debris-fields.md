# 전투 잔해장과 재활용 임무

## 목표와 범위

전투가 끝나면 전투에 참여한 함선 중 파괴된 함선의 일정 비율이 잔해로 행성 좌표 주변에 남고, 누구나 수확선으로 선착순 수거할 수 있게 한다. 사용자 간 전투와 우주괴수 전투(`space-monster-events.md`)에 모두 적용한다. 지갑 연결 여부와 무관하며, 괴수 처치 시 CGC를 받지 못하는 참가자의 대체 수단이 되기도 한다.

완료 조건: 전투 후 잔해장이 정확히 한 번 생성·누적되고, 수확선 임무가 선착순으로 수거해 귀환 시 행성에 자원을 더한다. 동시에 도착한 여러 수확선이 총량을 초과해 가져가지 않는다. 지도에 잔해가 표시된다.

## 확정된 결정

- 대상은 전투에 참여한 **함선**의 손실이다. 방어시설 손실은 제외한다(`combatSettings.defenseToDebris`가 켜진 경우만 포함, 현재 기본 꺼짐).
- 잔해 비율은 기존 `combatSettings.debrisFieldPercentage`(기본 30%)를 그대로 쓴다. 금속·수정을 따로 계산한다: `metal = floor(ratio × Σ 손실 함선의 금속 비용)`, `crystal`도 동일. 중수소는 잔해가 되지 않는다.
- 위치는 **방어 측 행성의 좌표**다. 괴수 전투는 괴수가 정착한 좌표다.
- 선착순: 수확선이 잔해장에 **도착한 순서**(`arrivalTime`, `_id`)대로 가져간다.
- 수확선(`recycler`)만 수거할 수 있고 수거량은 그 함대의 수확선 적재량 합이 상한이다. 금속을 먼저, 남은 적재량으로 수정을 가져간다.
- 잔해장은 자연 소멸하지 않는다. 같은 좌표의 전투는 누적된다.
- 괴수 유닛은 카탈로그 비용이 없으므로 `MonsterType.units[].wreck = { metal, crystal }`(유닛 1기가 파괴될 때의 잔해 기준값)을 어드민이 정하고, 같은 잔해 비율을 적용한다.

## 현재 코드와의 차이

- `CombatService.calculateDebris`는 손실 전체(방어시설 포함)의 금속+수정 합계에 비율을 곱한 뒤 7:3으로 나눈다. 이를 함선 전용·자원별 계산으로 바꾼다. 결과는 `BattleReport.result.debrisField`에 이미 저장되므로 보고서 형식은 유지한다.
- 잔해장 저장소와 `recycle` 임무 처리는 없다. `FleetMovement.mission` 열거형에는 `recycle`이 이미 있다.

## 설계

### 모델

`DebrisField`: `{ galaxy, system, planet }`(유니크 키 `coordinateKey`), `metal`, `crystal`, `updatedAt`. 수치는 정수다.

### 생성

전투 처리 트랜잭션(`FleetService`의 공격 분기, 괴수 분기) 안에서 보고서 저장과 함께 `DebrisField`를 `$inc` upsert한다. 보고서의 `movementId` 유니크 인덱스가 중복 적용을 막는 기존 구조를 그대로 쓰므로 재시도로 잔해가 두 번 쌓이지 않는다.

### 수거

- 출격(`mission: 'recycle'`): 편성에 수확선이 1척 이상 있어야 하고 목적지 좌표에 잔해가 있어야 한다. 자기 행성과 무관하게 모든 좌표를 목적지로 쓸 수 있다. 이동 시간은 기존 공식이다.
- 도착 처리: 한 트랜잭션에서 `DebrisField`를 읽고 `min(적재량, 보유)`를 계산해 조건부 갱신(`$inc` 음수, 값이 충분할 때만)으로 차감한다. 성공 시 `movement.cargo`에 더하고 귀환 전환한다. 잔해가 없으면 안내 문구와 함께 귀환한다. 도착 순서대로 처리되고 같은 문서의 쓰기 충돌은 트랜잭션 재시도가 직렬화한다.
- 귀환 완료 시 기존 로직이 적재 자원을 출발 행성에 더한다(별도 변경 없음).

### 표시

- `GET /api/game/galaxy`의 행성 항목과 별도 `debris` 목록에 좌표별 잔해량을 포함한다(인증된 모든 사용자에게 공개).
- 성계도·작전 지도에서 해당 궤도에 잔해 표식(금속·수정량)을 표시하고, 수확선이 있는 대기 함대를 드래그/클릭해 `recycle` 출격을 지원한다. 괴수 좌표에 잔해가 있으면 괴수 표식과 함께 표시한다.

## Phase 1

### 01. debris-model-and-generation

- 상태: completed
- 선행 단위: 없음
- 범위/결과물: `DebrisField`, 함선 전용·자원별 잔해 계산, 공격 분기에서 생성.
- 완료 조건: 방어시설 손실 제외; 같은 이동 재시도에서 중복 누적 없음; 보고서 값과 저장 값 일치.
- 검증: 서버 단위/통합 테스트(공격 후 잔해량, 재시도, 연속 전투 누적).

### 02. recycle-mission

- 상태: completed
- 선행 단위: 01
- 범위/결과물: 출격 검증, 도착 시 수거, 귀환 적재, 선착순 동시성.
- 완료 조건: 수확선 없는 편성 거절; 적재량·보유량 상한; 동시 도착에서 총 수거량이 잔해량 이하이고 도착 순서대로 지급; 빈 잔해 귀환.
- 검증: 동시 도착 통합 테스트(2~10개 함대), 귀환 후 행성 자원 증가.

### 03. debris-display

- 상태: completed
- 선행 단위: 02
- 범위/결과물: 갤럭시 API 포함, 지도 표식, 수확 출격 UI.
- 완료 조건: 잔해량이 갱신되어 보이고 드래그/클릭 출격이 동작; 모바일 조작 가능.
- 검증: 브라우저 테스트.
