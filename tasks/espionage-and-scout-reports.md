# 성계도 정찰 출격과 정보 보고

## 상태와 목표

- 상태: 전체 실행 단위 완료. 구현·통합 검증 및 현재 게임 코드 전체 커밋.
- 기준: 2026-10-05 다시 읽은 harness/SKILL.md 및 framework/docs/HARNESS.md. 현재 세션에서 실행 단위별 구현·검증을 수행하고 이 파일 한 곳에서 상태를 관리한다. 별도 모델 CLI와 phase/step 파일은 사용하지 않는다. 사용자가 후속 메시지로 테스트 완료 후 커밋을 명시적으로 요청했으므로 마지막 실행 단위에서 검증된 기능 변경을 커밋한다.
- 목표: 성계도에서 궤도를 선택하고 정찰 버튼을 누르면 이미 건조한 미배정 정찰선 1척이 출격한다. 도착 시점의 점령 상태·첩보 기술·주둔 전력을 기준으로 정보를 전달하고 탐지·요격·귀환을 처리한다. 오른쪽 목표 패널에서 최신 관측을, 보고서 영역에서 전체 기록을 확인한다.
- 사용자 확정 요구: 클릭 횟수에 따른 실제 정찰선 소비, 선행 건조 필요, 도착 후 정보 전달, 레벨·병력에 따른 정보 차등 및 파괴 가능성.
- 설계 기본안: 레벨은 기존 첩보 기술로 사용한다. 미배정 정찰선 1척씩 독립 임무로 출격한다. 여러 번 보내면 여러 시점의 관측을 받으며 횟수로 정보 단계를 올리지 않는다. 아래 정보 단계·확률로 구현하고 동작을 검증했다. 장기 플레이 밸런스 조정은 별도다.
- 완료 기준: 실제 게임 주소·실제 DB 연결에서 정찰 요청이 처리되고, 기존 계정·로그인·건조·함대 편성·공격·수송이 유지된다. 격리 테스트만 통과한 상태로 전체 완료를 표시하지 않는다.
- 기존 작업: tasks/fleet-formations-and-combat.md와 fleet-strike-map.md는 보존한다. 기존 미커밋 변경을 덮어쓰거나 되돌리지 않는다.

## 현재 코드 근거와 변경 경계

- server/data/catalog/ships.js: espionageProbe(정탐 드론)가 건조 가능한 함종으로 존재한다. 이동 속도·선체·건조 요구사항을 재사용한다.
- server/data/catalog/research.js: espionageTechnology(첩보 기술)가 존재한다. 별도의 정찰함대 레벨·경험치 체계를 추가하지 않는다.
- GalaxyView.js: 지도·궤도 목록 클릭이 동일한 오른쪽 상세 패널을 선택한다. 현재 적 목표에는 작전 목표 지정만, 빈 궤도에는 준비 중 식민 버튼만 있다.
- galaxySystem.js: 소유자·행성 이름·접속 상태만 공개한다. 정찰 정보는 공개 성계 API에 추가하지 않는다.
- FleetMovement: spy 임무 enum과 미배정 이동 문서가 가능하지만 실제 정찰 처리가 없다. FleetService.launch는 attack/transport와 formationId·점령 행성 ID만 허용한다.
- FleetService.processMovement와 socket tick: 이동 도착·귀환을 처리한다. 정찰 임무는 공격 전투 분기에 들어가지 않도록 명시적으로 분기한다.
- formationRules.availableShips: 다른 대기 함대에 예약한 수량을 제외할 수 있다. 정찰 출격 검증에도 사용한다.
- GameStateService: 주둔 함선·편성·임무·stateRevision을 함께 반환한다. 정찰 임무도 같은 스냅샷과 기존 실시간 갱신을 사용한다.
- BattleReport는 양쪽 전투 참가자를 전제로 한다. 빈 궤도 관측을 넣지 않고 ScoutReport를 별도로 만든다.
- 실제 DB는 앞선 복구에서 replica set oogame으로 전환했다. 구현 시작 시 현재 연결과 서버 상태를 재확인한다. DB 초기화나 새 DB로의 무통보 전환은 하지 않는다.

## 플레이 및 UI 설계

1. 성계도 궤도를 선택하면 오른쪽 상세 패널에 `정찰 · 1척`, 출발 행성, `출격 가능 N척`, 예상 도착 시간을 표시한다. 빈 궤도와 다른 플레이어 행성 모두 정찰 가능하다. 자기 행성은 버튼을 비활성화하고 이유를 보여준다.
2. 정찰선 0척이면 건조 화면으로, 전부 다른 함대에 예약됐으면 함대 편성 화면으로 이동할 수 있게 한다. 이동 중인 정찰선은 출격 가능 수량에 포함하지 않는다.
3. 버튼 한 번은 1척짜리 독립 출격 의도다. 3회 클릭은 서로 다른 requestId의 3개 임무다. 각 클릭을 서버 응답 전에도 접수하되 화면의 잠정 가용량을 차감해 초과 클릭을 막는다. 한 요청 처리 중이라는 이유로 모든 연속 클릭을 무시하거나 하나로 합치지 않는다.
4. 클릭 순간 출발 행성과 목적 좌표를 고정한다. 이후 목표를 바꿔도 이미 접수한 요청은 기존 목표로 향한다. 실패한 요청 수와 이유를 표시하고 실제 성공 횟수만 출격으로 센다.
5. 성공 시 주둔 수량에서 1척 차감하고 기존 전투 화면 아래 진행 중인 임무에 `정찰 · [좌표]`를 표시한다. 성계도 패널에도 해당 목표로 가는 정찰 임무·도착 대기 상태와 임무 바로가기를 제공한다.
6. 정보는 출격 직후 표시하지 않는다. 서버가 도착을 처리하면 `정찰 보고 도착` 알림과 목표 패널의 최신 관측 카드를 갱신한다. 카운트다운 0만으로 보고서를 만들지 않는다.
7. 최신 관측에는 관측 시각/경과 시간, 당시 점령자, 공개된 정보 단계, 탐지·요격 결과를 표시한다. 숨겨진 항목은 `미확인`, 실제 관측한 무병력은 `0척`으로 구별한다. 잠긴 정보는 공개 조건을 설명하되 상대의 숨겨진 기술 레벨을 노출하지 않는다.
8. 패널의 `정찰 기록`으로 목표별 보고서 목록과 상세를 열 수 있게 한다. 전투 화면에도 접을 수 있는 `정찰 보고` 영역을 마련한다. 모두 같은 보고서 컴포넌트를 사용한다. 기존 전투 보고는 그대로 유지한다.
9. 새 보고가 와도 이전 보고서를 덮어쓰지 않는다. 오래된 관측은 현재 값처럼 보이지 않게 하고, 현재 행성 ID/소유자와 다르면 `이전 점령 상태의 관측` 표시를 붙인다. 새 낮은 단계 보고서에 옛 높은 단계 데이터를 섞지 않는다.
10. 지도 선택·목표 변경·자동 갱신에도 키보드 포커스와 펼친 보고서를 보존한다. 모바일에서는 지도 다음에 목표 패널을 배치하고 44px 이상의 버튼, 가로 넘침 없는 카드, 클릭·키보드 조작을 지원한다.

## 정찰 판정 기본안

### 정보 단계

- A = 출발 행성의 첩보 기술(행성 우선, 기존 사용자 연구 fallback). 출격 시 저장한다.
- D = 도착 처리 시 목표 행성의 첩보 기술(동일 fallback). 서버 내부 판정에만 사용한다.
- 점령된 타인 행성: 정보 단계 = clamp(1 + A - D, 1, 4).

| 단계 | 해당 보고서에서 공개하는 항목 |
|---|---|
| 1 | 좌표·관측 시각·당시 점령자/행성 이름·금속/크리스탈/듀테륨 수량 |
| 2 | 단계 1 + 주둔 함선 종류별 수량 |
| 3 | 단계 2 + 방어시설 종류별 수량 |
| 4 | 단계 3 + 건물/연구 레벨 |

- 관측 시 정산된 자원과 건조 완료를 반영한다. 주둔량은 배정·미배정 함선을 모두 포함하고 이동 중인 함선은 제외한다.
- 빈 궤도: 도착 당시 미점령이라는 사실과 좌표·시각만 보고한다. 자원·병력은 0으로 만들어 표시하지 않는다. 환경/매장량 생성은 범위 밖이다.
- 출격 후 점령자/행성이 바뀌면 좌표의 도착 당시 소유자를 정찰한다. 출격 당시 ID가 같아야 한다는 공격용 계약을 정찰에 적용하지 않는다.
- 도착 당시 자기 소유가 됐다면 `현재 아군 행성` 보고를 남기고 요격 없이 귀환한다. 중복 점령 등 좌표 데이터 충돌은 타인의 정보를 임의 선택하지 않고 `관측 대상 확인 불가`로 기록해 귀환한다.

### 탐지와 요격

- 점령된 타인 행성 탐지 확률 제안값: clamp(50 + 15 × (D - A), 5, 95)%.
- 1척 임무마다 1회 판정한다. movementId와 서버 비밀 키 기반의 안정된 판정값을 사용해 트랜잭션 재시도·타이머 중복·서버 재시작이 결과를 바꾸지 않게 한다. 판정/규칙 버전을 보고서에 저장하며 서버 비밀 값은 API에 반환하지 않는다.
- 도착 당시 활성 카탈로그 기준 attack > 0인 주둔 함선 또는 방어시설이 1기 이상이면 요격 전력 있음. 수송선·정찰선·태양광 위성·공격력 없는 방어물만으로는 요격하지 못한다.
- 미탐지: 정보 전송 후 귀환. 탐지 + 요격 전력 없음: 정보 전송 후 귀환하며 상대에게 침입 알림. 탐지 + 요격 전력 있음: 정보 전송 후 1척 격추, 임무 완료, 귀환·환급 없음.
- 이번 버전은 수집 정보 전송 후 요격 순서로 한다. 격추돼도 허용된 단계의 보고서를 받는다. 일반 공격 전투 시뮬레이션을 실행하지 않으며 정찰로 상대 함선·방어시설을 파괴하지 않는다.
- 상대에게는 탐지된 경우만 좌표·시각·정찰자·요격 결과를 알린다. 공격자가 받은 자원/병력 정보·정보 단계·양쪽 기술 차이는 전달하지 않는다. 오프라인에서도 탐지 기록을 재조회할 수 있게 한다.
- 정확한 탐지 확률이나 요격 전력 존재 여부는 출격 전에 실제 적 DB를 읽어 클라이언트에 표시하지 않는다. 미관측 위험은 `요격 위험 미확인`으로 보여준다.

## 임무·데이터·API 계약

- 자동 정찰 출격은 저장된 1함대/2함대 편성을 만들거나 이름 번호를 소비하지 않는다. fleet={espionageProbe:1}, mission=spy, formationId=null인 실제 FleetMovement를 생성한다.
- 출격 수량 검증·주둔 함선 차감·이동 생성은 같은 트랜잭션이다. 편성 예약·동시 출격·건조 완료·공격 피해와 동일한 사용자 버전/수량 경계를 사용한다.
- 기존 여행 시간 계산과 정찰선 이동 성능을 사용한다. 이번 범위에서는 현재 공격/수송에도 없는 별도 연료 차감 규칙을 정찰에만 도입하지 않는다. cargo=0, speed=100으로 고정한다.
- movement에 spyContext={attackerEspionageLevel, rulesVersion}, scoutReportId를 추가한다. 완료/귀환 상태는 기존 상태를 사용하고 결과는 보고서와 notice에서 구분한다. 최초 정찰 출격 정보와 현재 생존 함선 수량을 보존한다.
- ScoutReport: movementId(고유), ownerUserId, originPlanetId/좌표, targetCoordinates, observedAt, 당시 targetPlanetId/targetUserId/name, outcome(empty/occupied/friendly/unavailable), informationTier, 공개된 sections, detected, intercepted, initialProbeCount/survivorCount, rulesVersion. 요격 판정에 사용한 민감한 내부 값은 공개 sections와 분리하거나 저장하지 않는다.
- 보고서 공개 sections에는 허용된 필드만 저장한다. 잠긴 항목은 생략한다. 비밀 내용을 전부 저장·전달한 뒤 화면 CSS로 숨기지 않는다.
- 인덱스: ScoutReport movementId 고유, ownerUserId+observedAt+_id, ownerUserId+targetCoordinates+observedAt+_id. 탐지 목록용 targetUserId+detected+observedAt+_id. 실제 조회 패턴에 맞춰 적용한다.
- `POST /api/game/scouts`: {requestId, originPlanetId, destination:{galaxy,system,planet}}. 성공 201 {fleet, snapshot, snapshotPending}. quantity/fleet/formationId/cargo/기술 레벨 등 임의 조작 필드는 거부한다. 재시도 동일 ID/동일 내용은 같은 이동을 반환하고 다른 내용이면 409.
- `GET /api/game/fleet-requests/:requestId`: 기존 사용자별 요청 결과 조회를 재사용한다. 정찰 요청에도 소유자 제한을 적용한다.
- `GET /api/game/scout-reports`: 본인 보고서만, 선택적 목적 좌표·cursor·limit(기본 20, 최대 50) 필터. observedAt와 _id로 안정된 역순 페이지네이션. 클라이언트 전체 다운로드 후 필터링하지 않는다.
- `GET /api/game/scout-reports/:id`: 소유자 상세 조회. 다른 사용자 보고서 ID는 404.
- `GET /api/game/scout-alerts`: 본인이 탐지한 침입만 조회. 서버가 위에서 정한 알림 전용 필드만 반환한다. 보고서 전체를 재사용해 숨겨진 정보를 보내지 않는다.
- 새 보고서와 도착/귀환 상태를 같은 트랜잭션에서 확정한다. 임무당 보고서 1개, 생존 함선 환급 1회, 격추 함선 환급 0회를 보장한다. 알림은 커밋 이후 사용자 room에만 전송한다.
- 스냅샷은 기존 임무 목록·함선·stateRevision을 유지하며 정찰 결과 링크를 포함한다. 전체 보고서 이력을 스냅샷에 넣지 않는다. 보고서는 별도 API로 조회한다.
- 목표 패널/알림 영역은 재접속·창 재활성화·활성 화면 polling 때 보고서를 다시 조회한다. 소켓이 유실돼도 관측 결과를 복원한다.

## 실패와 복구

- 출격 가능 수량은 서버 권위다. 2척에 3건 동시 요청이면 정확히 2건만 성공하고 나머지 1건은 명시적 부족 오류로 끝난다. 예약된 정찰선은 소비되지 않는다.
- 각 클릭의 requestId와 고정된 주문을 사용자별 sessionStorage에 저장한다. 응답 유실은 새 ID로 재출격하지 않고 결과 확인/동일 요청 재시도로 복구한다. UI의 잠정 수량과 서버 스냅샷 차감은 중복 적용하지 않는다.
- 원래 요청이 아직 커밋되지 않은 404를 확정 실패로 보지 않는다. 권한 변경·계정 전환 시 이전 계정의 요청/보고서를 새 계정에 적용하지 않는다.
- 공개 API 자체에 적 병력·자원·정찰 판정값이 새어나오지 않게 검증한다. 적 보고서·침입 알림·임무 ID 접근도 소유자별로 제한한다.
- 도착·귀환 서버 재시작/중복 tick/트랜잭션 오류에서도 정찰 판정·보고서·귀환 차감을 중복 실행하지 않는다. 도착 정보를 실제 처리 시점 observedAt로 명시한다.
- 출발 행성이 사라졌으면 생존 정찰선을 임의 삭제하거나 다른 행성에 환급하지 않고 기존 복구 notice 경로로 남긴다.
- 구형 spy 이동 문서가 있다면 1척 고정 입력을 소급 강제하지 않는다. 실제 저장된 정찰선 수량과 출발 연구 fallback을 사용하고, 여러 척인 구형 임무가 탐지·요격되면 해당 정찰선 전체 손실로 처리한다. spy에 비정찰 함선이 섞인 구형 임무는 자동 전투/임의 삭제 없이 복구 notice 대상으로 남긴다.
- DB 조건이 미충족이면 출격 전에 503, 함선 차감 0. 기존 로그인·건조·함대 경로는 계속 유지한다. 환경 문제를 기능 완료로 숨기지 않는다.

## 검증 실행과 환경 구분

- 순수 규칙/상태 검사: 새 테스트 파일을 server/test의 기존 npm test 수집 규칙에 포함한다. 클라이언트 테스트가 필요한 경우 현재 GameState 테스트 방식에 맞춘다.
- DB 통합: FLEET_TEST_MONGODB_URI의 별도 _test DB를 사용한다. 새 정찰 통합 파일도 DB 이름 guard·finally cleanup을 갖춘다. 기존 실제 DB와 UI 미리보기 DB를 테스트 초기화 대상으로 쓰지 않는다.
- 브라우저: 현재 Playwright Chrome 기반 검사에 정찰 경로를 추가한다. 시간 단축은 격리 테스트 DB 임무 시각에만 적용하며 게임 이동 공식을 바꾸지 않는다.
- 통합 명령: `npm --prefix server test`, `npm --prefix ogame-3d run build`, `npm --prefix ogame-3d run test:fleets`와 구현 시 추가될 정찰 browser 검사. 필요한 DB URI는 격리 DB를 명시해 주입한다.
- 실제 환경: 테스트 완료 후 기존 주소/DB 연결에서 추가 확인한다. 계정·데이터 초기화, 임무 전체 삭제, 실제 이동 시간 조작은 하지 않는다. agent 생성 검사 데이터만 정확한 ID로 정리한다.
- 기록에는 순수/격리 DB/browser/실제 환경 확인을 나눠 적는다. 물리 모바일 Safari·원격 배포는 수행하지 않으면 미실행으로 남긴다.

## 범위와 남은 결정

- 범위 안: 1클릭 1척 자동 정찰, 기존 건조/연구 활용, 빈·점령 궤도, 4단계 관측, 탐지/요격, 실제 귀환, 목표별 최신 정보 및 전체 정찰 이력, 상대 탐지 알림, 반복 클릭/중복/재접속 복구, 기존 기능 회귀.
- 범위 밖: 정찰 다척 선택·합동 정찰·편성 경험치·상대에게 허위 정보·정찰 전투 라운드·요격 전력 피해·자동 반복 정찰·빈 행성 환경 생성·식민·새 연료 규칙·전체 보고 메뉴 개편.
- 구현 전 사용자 결정이 반드시 필요한 항목은 현재 없다. 정보 단계/확률/격추 후 정보 전송은 제안 기본값으로 명시했으며 사용자의 수정 지시가 있으면 이 설계를 조정한다.
- 커밋 승인: 테스트 완료 후 이상 없으면 커밋하라는 사용자의 명시적 후속 요청이 있다. 단계마다 재승인을 요구하지 않는다. 실패·미검증 상태를 통과로 처리해 커밋하지 않는다.
- 커밋 범위 확정: 사용자가 현재 게임 코드 변경 전체를 함께 포함하도록 응답했다. 기존 함대·카탈로그·기술트리 기반 변경 및 테스트·문서도 함께 검증해 커밋한다. 비공개 DB 백업, 환경 비밀 값, 개인 도구 설정은 제외한다.
- 커밋 경계: 구현 시작 시 기존 unstaged/staged 변경을 기록해 소유 범위를 구분한다. `git add -A`로 타 작업을 묶지 않는다. 필요한 기존 미커밋 의존성이 있으면 실제 diff·작업 기록을 확인해 커밋 범위를 정리하며, 의존 변경이 빠진 커밋을 독립적으로 검증됐다고 표시하지 않는다. 기능 범위 밖 변경이 반드시 필요한 경우 그 근거와 범위를 먼저 정리한다.
- 후속 작업: 사용자가 실제 플레이에서 발견한 문제나 밸런스 조정 요청이 있으면 해당 단위의 범위와 검증을 갱신한다.

## 현재 검증 결과

- P1-S1/P1-S2/P2-S1/P2-S2: 정찰 규칙 및 replica set HTTP 통합 3개 통과. 예약 보호·동시 출격·동일 ID·도착 전 정보 없음·중복 도착/귀환·빈 궤도·격추 무환급·보고서 권한/필드 제한·cursor 검증 확인. 실제 환경 및 browser 확인도 아래 P3 통합 검증에서 완료했다.
- P3-S1/P3-S2: 클라이언트 요청·수량·계정 전환/응답 유실 검사 2개 및 Chrome 정찰 E2E 2개 통과. 실제 건조→연속3클릭→보고/귀환·빈 궤도·새로고침·모바일·0척·응답 유실 무중복 확인. 자동 갱신 중 출격 버튼 DOM을 유지해 클릭 유실을 방지했다.

- P3-S3 전체 서버 검사: 66개 통과, 실패/skip 0. replica set DB(27029)의 함대·좌표·정찰 통합과 standalone DB(27030)의 기존 게임 유지/새 기능 503 무차감 검사를 함께 실행했다.
- P3-S3 전체 Chrome E2E: 기존 함대 4개 + 정찰 2개, 총 6개 통과. 정찰선 건조→3클릭→3임무→보고·귀환, 빈 궤도, 응답 유실 후 동일 ID 복구, 모바일 390px, 수량 0·자기 행성 차단을 확인했다. 데스크톱·모바일 결과 화면을 직접 확인했다.
- P3-S3 빌드와 diff 검사 통과. 기존 번들 크기 500kB 경고는 남아 있으며 빌드 실패는 없다.
- P3-S3 실제 환경: 기존 localhost:3000 서버 및 replica set oogame에 임시 검사 계정 2개만 생성해 로그인→3출격→실제 tick 도착/귀환→보고 3개(tier 4)→수량 3척 복구→로그인 스냅샷 재조회까지 확인했다. 실제 임무 시각은 조작하지 않았다. 검사 계정·임무·보고·큐를 ID로 정리하고 원래 계정 수 유지 확인. 최초 요청은 파일 저장으로 인한 nodemon 재시작 중 연결 실패했고, 서버 재기동 후 동일 검사를 다시 실행해 통과했다.
- 미실행: 원격 배포, 물리 모바일 Safari, 장기 플레이 밸런스. 브라우저 E2E는 격리 DB/Chrome, 실제 서버 검사는 HTTP와 실제 DB/tick 기준이다.
- 커밋 단위 조정: 정찰이 기존 미커밋 함대·카탈로그·기술트리 변경에 의존하며 사용자가 현재 게임 코드 전체 포함을 명시했다. 독립되지 않은 기반과 기능 단위를 함께 검증해 마지막 커밋으로 묶는다. 개인 설정·비공개 DB 백업·환경 비밀 값은 제외한다.
- P3-S4: 현재 게임 코드·의존 기반·테스트·문서 112개 파일을 함께 스테이징했다. staged diff --check 및 비밀 키 패턴 검사 통과. 개인 .serena 설정과 화면 캡처는 스테이징하지 않았다. 커밋 ID는 Git log와 최종 응답에서 제공한다. push는 하지 않는다.
- 커밋 복구: ECC pre-commit이 테스트 고정 비밀번호와 임시 검사 비밀번호의 문자열 prefix를 자격 정보로 탐지해 첫 커밋을 거부했다. 훅을 우회하지 않고 테스트/seed/live 비밀번호를 randomUUID 생성으로 교체했다. preview 비밀번호는 비공개 `/tmp` fixture에만 저장한다. 변경된 검사 경로를 다시 실행한 뒤 커밋한다.
