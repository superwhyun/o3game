# fleet-strike-map

## 목표와 범위

- 목표: 함대 화면에 성계도와 같은 궤도도 기반 "작전 지도"를 넣는다. 은하/성계를 고르면 그 성계 궤도가 나오고, 보유 함선으로 공격대를 편성한 뒤 공격대 토큰을 행성으로 드래그 앤 드롭하면 출격한다. 드래그 중에는 출발점→포인터로 화살표(도착 예정 시간 포함)를 그린다.
- 범위: 클라이언트 UI(ogame-3d). 출격은 기존 `POST /api/game/fleets`(mission: attack/transport)를 그대로 사용한다. 서버 API·DB 변경 없음.
- 범위 밖: 진행 중 함대의 지도 위 이동 표시, 귀환/정찰/식민 임무, 속도 % 조절 UI.

## 완료 조건

- [x] 함대 화면 상단에 작전 지도(궤도도) + 은하/성계 이동 + 본거지 버튼이 표시된다.
- [x] 보유 함선(속도 0인 함선 제외)을 수량 지정해 공격대를 편성할 수 있고, 편성 요약(척수·공격력·적재량)이 보인다.
- [x] 공격대 토큰을 드래그하면 화살표가 따라오고, 유효 목표(타 제국/다른 아군 행성) 위에서 강조 + 도착 예정 시간이 표시된다. 빈 궤도·본거지 위에서는 무효로 표시되고 놓아도 출격하지 않는다.
- [x] 놓으면 확인 카드(목표·임무·ETA)가 나오고, 확인 시 출격 → 스냅샷 동기화·알림·작전 현황 갱신.
- [x] 마우스와 터치(Pointer Events) 모두 동작한다. 드래그가 어려운 경우를 위해 행성 선택 후 "출격" 버튼 경로도 있다.
- [x] 성계도의 "작전 목표 지정"은 작전 지도를 그 성계·행성으로 연다.
- [x] 기존 수동 명령서(좌표 입력 폼)와 작전 현황은 유지된다.
- [x] 이동 시간 계산은 서버 `calculateTravelSeconds`와 동일함을 테스트로 보장한다.
- [x] 서버 테스트 통과, vite build 통과, 실제 화면(1440/390)에서 드래그 출격 E2E 확인.

## 설계와 주요 결정

- 변경 경계: `ogame-3d/src/ui/views/{OrbitChart,GalaxyView,StrikeMap}.js`, `ogame-3d/src/ui/views/dragArrow.js`, `ogame-3d/src/data/fleetMath.js`, `ogame-3d/src/ui/strike.css`, `UIManager.renderFleet`, `server/test/fleetMathParity.test.js`.
- OrbitChart 분리: 성계도와 작전 지도가 같은 궤도 표현을 쓰도록 렌더링/애니메이션/좌표 조회를 한 컴포넌트로 모은다(중복 방지).
- 드래그: HTML5 DnD 대신 Pointer Events. 터치 지원, 화살표를 직접 그릴 수 있음. 드래그 중에는 공전 애니메이션을 멈춰 목표가 움직이지 않게 한다.
- 화살표: 화면 전체 고정 오버레이 SVG에 2차 베지어 곡선 + 화살촉. 출발점은 지도에 본거지가 보이면 본거지 행성, 아니면 토큰 위치.
- 목표 판정: `document.elementFromPoint` → `[data-slot]`. 유효 조건은 서버 규칙과 동일(행성이 있음, 출발지와 다름). 임무 기본값은 타 제국=공격, 아군=수송.
- 서버 규칙상 속도 0 함선(태양광 인공위성)은 출격 불가 → 편성 목록에서 제외.

## 작업 중 발견·수정한 문제

- 서버 `assertCargoAvailable`가 보유 자원을 정수로 강제 → 생산으로 누적된 소수 자원 때문에 **모든 출격이 실패**하던 기존 버그. 보유량은 유한·비음수만 검사하고 내림값과 비교하도록 수정(테스트 선작성).
- 작전 지도 첫 진입 시 본거지 좌표(행성 번호 포함)를 목표로 오인해 확인 카드가 뜨던 문제 → 목표는 `show(coords, { targetSlot })`로만 지정.
- 확인 카드 상태에서 스크롤 시 화살표 좌표가 어긋남 → scroll/resize 시 재계산.
- 모바일에서 하단 알림 토스트가 공격대 토큰을 가림 → 좁은 화면에서 알림을 상단으로 이동.
- 작전 현황·전투 보고의 영문 표기(ATTACK flying 등) 한글화.
