# 성계도 함대 이동 표시

## 목표와 범위

성계도에 현재 진행 중인 모든 사용자의 함대 항로를 화살표로 표시한다. 현재 성계 내부 이동, 다른 성계에서 유입되는 이동, 외부로 나가는 이동과 귀환을 지원한다. 현재 세션에서 아래 실행 단위에 따라 구현한다. 이 문서는 scaffold_task.py로 생성한 실행 단위 틀을 구체화한 계획이다.

완료 조건: 타 사용자 이동을 포함한 실제 출격이 지도에 반영되고, 내부·외부·귀환 방향과 시간 표시가 정확하며, 완료된 임무가 사라진다. 기존 정찰·개척·드래그 출격·행성 선택 기능을 유지한다. 검증을 통과한 의미 있는 단위와 기록을 함께 커밋한다.

## 설계와 주요 결정

### 표시 규칙

- 현재 성계에 출발점 또는 도착점이 있는 flying/returning 임무를 표시한다. 그 성계와 무관한 이동은 표시하지 않는다. 성계를 통과하는 실제 우주 좌표 경로는 현재 데이터에 없으므로 추정하지 않는다.
- 내부 이동: 해당 궤도에서 다른 궤도로 휘어진 화살표. 귀환은 반대 방향이다.
- 외부 이동: 지도 테두리에 외부 성계 표식 `[은하:성계]`를 두고 해당 궤도와 연결한다. 외부 궤도 번호와 행성명은 공개하지 않는다. 유입·유출 모두 지원한다. 같은 성계 번호가 다른 은하에 존재하므로 은하 번호를 함께 표시한다.
- 외부 표식의 위치는 겹침을 줄이기 위한 도식적 배치이며 실제 우주 방향을 뜻하지 않는다. 시간 진행 표시도 항로 전체 진행률을 뜻한다.
- 내 함대는 청록색으로 고정, 다른 사용자는 안정적인 ownerKey 기반 색상으로 구분한다. 이름/배지/범례를 함께 표시해 색상이 중복되거나 색을 구별하기 어려워도 구분한다. 사용자 색상과 귀환 여부는 독립적이며 귀환에 점선과 방향을 사용한다.
- 항로를 따라 작은 함대 표식이 시간에 따라 이동한다. 화살표 선택 또는 키보드/모바일 목록 선택 시 소유자·이동/귀환·현재 성계 내 궤도·외부 성계·도착까지 남은 시간을 표시한다.
- 모든 임무 종류를 표시하며 타 사용자 정찰선도 이동의 존재는 보인다. 타 사용자 함선 종류/수량/자원/편성명/임무 종류/정찰 결과는 노출하지 않는다. 상세 병력 확인은 기존 정찰 규칙을 유지한다. 내 임무는 기존 소유자 전용 정보를 연결한다.
- 기본 필터는 전체이며 내 함대/다른 사용자/내 행성으로 오는 이동을 선택할 수 있다. 여러 항로가 겹치면 곡률을 달리한다. 같은 소유자·항로·상태의 다수 임무는 묶어 `N개 이동`으로 표시하고 목록에서 개별 이동을 확인한다. 완료·취소 임무는 지도에서 제외한다.

### 공개 계약과 변경 경계

- `GET /api/game/galaxy/traffic?galaxy=&system=`: 인증된 사용자에게 요청한 성계의 항로 요약과 serverTime/observedAt를 제공한다. 기존 `/galaxy`의 행성 목록 계약은 유지한다.
- 개별 이동 목록은 cursor/limit 페이지네이션을 적용한다. 항로 요약은 전체 일치 임무를 DB에서 집계해 구성하며 개별 목록의 첫 페이지만 표시되는 것을 전체 이동으로 오해하게 만들지 않는다. 페이지 수집 중 변동과 중복은 이동 ID로 처리한다.
- 공개 투영: 표시용 이동/항로 ID, ownerKey/username/isSelf, flying/returning 상태, 현재 이동 구간의 시작/종료 시각, 현재 성계 내 끝점 `{planet}` 또는 외부 끝점 `{galaxy,system}`. 서버에서 외부 궤도를 제거한다. DB 원본이나 소유자 전용 formatFleetMovement를 그대로 반환하지 않는다.
- flying 구간: origin → destination, startTime → arrivalTime. returning 구간: destination → origin, returnStartTime → returnTime. 새 귀환에는 실제 전환 시각 returnStartTime을 저장한다. 기존 데이터는 returnTime에서 원래 비행 시간을 뺀 값으로 호환한다.
- 도착 시각이 지났어도 아직 flying/returning 상태면 진행률 100%에 도착 처리 중 표시한다. 클라이언트가 임의로 귀환/완료를 확정하지 않는다. 새 상태를 받으면 구간이 전환되거나 항로가 제거된다.
- `FleetMovement`에서 상태와 origin/destination 성계 필터용 복합 인덱스를 검토하고 실제 쿼리 계획으로 검증한다. 현재 성계 조건은 galaxy와 system이 동시에 일치해야 한다.
- 예상 변경: FleetMovement 모델, FleetService/ScoutService 귀환 시각, 새 교통 조회 서비스/라우트, apiService, GalaxyView, OrbitChart 및 지도 전용 FleetTrafficLayer, UIManager, galaxy.css, 전용 서버/브라우저 테스트.
- OrbitChart의 SVG 좌표계 안에 지속 항로 레이어를 둔다. 기존 document.body dragArrow는 출격 확인용으로 유지한다. 행성이 움직일 때 끝점도 갱신하고 지도 재렌더/선택 시 레이어가 소실되지 않게 한다. 화살표는 행성 클릭·드래그 판정을 가로막지 않으며 별도 넓은 hit 영역/목록으로 선택한다.

### 동기화와 실패 처리

현재 소켓은 임무 소유자/전투 대상에게만 알림을 보내므로 제3자의 이동 갱신에는 충분하지 않다. 최초 구현은 성계도를 보는 동안 기존 8초 갱신 주기를 재사용해 교통 API를 조회한다. 화면/탭이 숨겨지면 중지하고 복귀 시 즉시 갱신한다. 내 출격과 임무 변경 알림 시 즉시 교통 갱신을 추가한다. 별도 성계 room은 이번 범위에 넣지 않는다.

빠른 성계 전환은 요청 세대/좌표를 비교해 이전 응답을 버린다. 로그아웃과 계정 변경 시 표시·요청·선택을 초기화한다. 실패하면 마지막 항로와 마지막 갱신 시각을 유지하고 연결 지연을 표시한다. 재연결 성공 시 상태를 교체한다. 반영 지연은 통상 최대 갱신 주기이며 서버 도착 처리는 현재 5초 틱을 따른다. 경로 진행률과 시간은 serverTime으로 클라이언트 시계 오차를 보정한다.
