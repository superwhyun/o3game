# 우주괴수 이벤트

## 목표와 범위

게임 어드민이 기간을 정해 거대 우주괴수를 등장시킨다. 괴수는 주인 없는 행성 좌표에 정착하고 하루에 한 번 다른 좌표로 이동한다. 여러 사용자가 기존 함대 출격·전투로 공격해 괴수를 처치하면 유효 피해량에 비례해 CGC 보상을 받는다. 괴수는 종류별로 능력치와 보상 풀이 다르며 어드민 화면에서 정의한다.

완료 조건: 어드민이 괴수 종류와 이벤트를 만들고, 사용자가 괴수 좌표로 출격해 누적 피해를 입히며, 처치 시 지갑이 연결된 참가자에게 기여도 비례 CGC가 정확히 한 번씩 지급된다. 기간 내 처치하지 못하면 보상이 없다. 괴수 이동·동시 도착·서버 재시작에서도 상태가 일관된다. 기존 사용자 간 전투·식민화·정찰 동작은 유지된다.

## 확정된 결정

| 항목 | 결정 |
|:--|:--|
| 괴수 위치 | 주인 없는 행성 좌표에 정착. 천천히 이동한다(주기는 이벤트별 설정, 기본 72시간) |
| 이동 후보 | 활성 플레이어 행성에서 일정 거리 이내의 빈 궤도만(A안) |
| 표적 소실 | 도착했는데 괴수가 없으면 전투 없이 즉시 귀환(C안, 기본 규칙) |
| 기여도 | 괴수 선체에 실제로 들어간 유효 피해량. 1인 상한 없음 |
| 분배 | 풀 전액을 지갑이 연결된 참가자의 유효 피해 비율로 분배. 참가상·최소 기여 조건 없음 |
| 보상 | CGC만. 괴수 종류(이벤트)마다 어드민이 보상 풀을 정한다. 지갑 미연결 계정은 CGC 보상 없음. 기간 내 처치 실패 시 보상 없음 |
| 자원 교환 | 지원하지 않는다. 예산은 관리자 배분·운영자 예치·상점 판매 수입으로 채워진다 |
| 괴수 정의 | 어드민 UI에서 편집 |
| 전투 | 기존 8웨이브 전투를 재사용. 약탈 없음 |

## 미정·파생 규칙(확인 필요)

- **지갑 미연결 계정의 몫.** "보상 없음"의 처리를 이렇게 정했다: **공격 시점에 지갑이 연결돼 있던 피해만 보상 대상에 합산**하고, 분모도 그 합계다(연결 전 피해는 누적 기록만 하고 보상에 쓰지 않는다). 풀은 전액 분배된다. 처치 시점 기준으로 바꾸면 처치 직전 연결로 몫이 바뀌는 문제가 있다. 다른 규칙을 원하면 알려 달라.
- **이동 주기.** "천천히 이동"이므로 기본값을 72시간으로 잡았다. 구체적인 값은 이벤트별 `moveEveryHours`와 후보 거리 `maxDistance`(기본 20)로 어드민이 정한다.
- **지갑 미연결 참가자의 대체 보상.** 아래 "지갑 미연결 참가자" 절의 세 안 중 아직 선택하지 않았다. CGC 보상 로직은 이 선택과 독립이다.
- **재생.** 괴수 체력 재생은 기본 없음이다(`regenPerHour: 0`). 설정으로 열어 둔다.
- **예산.** 보상 풀 전액을 정산하려면 게임 예산이 충분해야 한다. 신규 게임의 예산은 0이므로 이벤트 전에 관리자 배분이나 운영자 예치가 필요하다. 부족하면 정산이 `BLOCKED`로 대기하고 예산이 확보되면 자동으로 이어서 지급한다.

## 현재 코드와의 차이(변경 필요 지점)

| 항목 | 현재 | 필요한 변경 |
|:--|:--|:--|
| 공격 목표 | `FleetService`가 `User.findOne({ planets: $elemMatch })`로 유저 행성만 찾고 없으면 `TARGET_CHANGED` | 괴수를 목표로 삼는 분기 |
| 전투 유닛 | `initializeUnit`이 카탈로그의 ship·defense만 인식 | 괴수 전용 인라인 스탯 주입(카탈로그에 넣으면 모든 행성 스키마·조병창에 노출됨) |
| 체력 지속 | 전투 결과가 생존 유닛 수만 반환, 손상된 체력은 버림 | 방어측 잔여 체력 배열 반환 |
| 피해 집계 | `executeFire`의 damage는 실드에 막힌 분량을 포함한 원시값 | 선체에 실제 적용된 피해(남은 체력 상한)를 따로 집계 |
| 좌표 점유 | 유저 행성만 점유로 판정(`loadOccupiedCoordinateKeys`, `pickHomeCoordinate`, 식민화) | 괴수 좌표를 점유로 취급 |
| 동시 도착 | 한 괴수에 여러 사용자 쓰기 | 문서 버전 CAS와 트랜잭션 재시도 |

## 설계와 주요 결정

### 데이터

- `MonsterType`: `typeId`, `name`, `description`, `units: [{ unitId, name, count, wave(0~7), stats: { hull, shield, attack, rapidFire, combatClass } }]`, `techs: { weapons, shield, armor }`, `model`(3D 절차 생성 사양), `regenPerHour`, `defaultPoolMicro`. 검증: 유닛 총 수 상한(예: 합계 2,000), 스탯 범위, 웨이브 범위.
- `MonsterEvent`: `eventId`, `typeSnapshot`(생성 시 `MonsterType`의 전체 복사본, 이후 종류를 수정해도 진행 중 이벤트는 불변), `startsAt`, `endsAt`, `status`(`SCHEDULED` → `ACTIVE` → `DEFEATED` → `SETTLING` → `SETTLED` / `EXPIRED` / `CANCELLED` / `BLOCKED`), `poolMicro`, `location { galaxy, system, planet }`, `moveEveryHours`, `maxDistance`, `nextMoveAt`, `locationHistory`, `state`(유닛 종류별 잔여 체력 배열), `version`(낙관적 동시성), 타임스탬프.
- `MonsterContribution`: `{eventId, userId}` 고유, `username`, `damageTotal`, `damageEligible`(지갑 연결 상태에서 입힌 피해), `attacks`, `fleetLosses`, `lastAt`, `rewardMicro`, `rewardRef`.
- `MonsterBattleLog`: `{eventId, movementId}` 고유. 같은 이동의 중복 적용을 막는다.
- 피해량은 `Number`(정수 체력 단위)로 저장한다. 보상 계산만 `BigInt`로 한다.

### 지갑 미연결 참가자

지갑이 없는 참가자는 CGC를 받지 못한다. 처치 후 대체 보상은 아래 중 하나로 정한다(미정).

| 안 | 내용 | 비고 |
|:--|:--|:--|
| A. 잔해(데브리) | 처치 시 괴수 좌표에 잔해장이 생기고 재활용선(`recycler`)으로 수거 | 현재 코드에는 잔해장이 없다. 전투가 `debrisField`를 계산해 보고서에만 저장하고 `recycle` 임무는 구현돼 있지 않다. 잔해장 모델·재활용 임무·수거 규칙을 새로 만들어야 한다. 수거는 선착순이고 지갑을 연결한 참가자도 수거할 수 있다 |
| B. 기여도 비례 자원 | 미연결 참가자에게 유효 피해 비율로 게임 내 자원 지급 | 새 임무 없이 정산 단계에서 처리. 자원이 새로 생성되므로 총량을 괴수 종류별로 어드민이 정한다 |
| C. 보류 | 대체 보상 없음 | 이후 잔해장을 일반 기능으로 구현할 때 연결 |

A를 택하면 괴수 종류에 `debris: { metal, crystal }`(처치 시 생성량)과 `debrisExpiresHours`를 추가한다. 괴수 유닛은 카탈로그 비용이 없어 전투가 계산하는 `debrisField`를 쓸 수 없으므로 고정 생성량을 쓴다.

### 괴수 생애주기와 이동(지연 정산)

`MonsterService.settleEvent(eventId, now)`는 멱등이며 다음을 처리한다: 시작 시각 도달 시 `ACTIVE`와 최초 정착, 기간 만료 시 `EXPIRED`(보상 없음), 이동 시각 도달 시 재배치. 호출 지점: 성계/교통 조회, 출격 검증, 도착 처리, 어드민 조회, 그리고 60초 주기 스위퍼(트래픽이 없어도 만료·정산이 진행되도록). 서버가 꺼져 있었던 기간의 이동은 몰아서 하지 않고 현재 기준으로 한 번만 재배치한다.

**후보 좌표(A안)**: 아래를 모두 만족하는 좌표에서 시드 난수로 균등 선택한다. 결과는 `locationHistory`에 기록한다.

- 유저 행성이 없고 다른 활성 괴수가 없다.
- 진행 중인 `colonize` 임무(`flying`/`returning`)의 목적지가 아니다.
- 최근 N일(기본 14일) 내 접속한 사용자의 행성에서 이동 거리(`Δ은하+Δ성계+Δ궤도`, `fleetMath`와 같은 척도)가 `maxDistance` 이하다.
- 직전 위치와 같은 성계가 아니다.

후보가 없으면 위치를 유지하고 1시간 뒤 다시 시도한다. 이동 거리에 대한 참고: 단위당 비행 시간은 `350000 / 속도`초이므로 거리 20은 속도 5,000에서 약 24분, 속도 100(데스스타)에서 약 19시간이다. 느린 함선은 주기를 길게 두거나 거리를 줄이는 것으로 조정한다.

**좌표 점유**: `ACTIVE`/`DEFEATED`(정산 대기 포함) 괴수의 좌표를 점유로 취급한다. 홈 행성 배정(`pickHomeCoordinate`의 점유 집합), 식민선 출격 검증, 식민선 도착 처리가 모두 이를 확인하고 충돌하면 `TARGET_CHANGED`로 처리한다. 괴수 정착과 식민 도착의 경쟁은 이벤트 문서 `version`을 같은 트랜잭션에서 읽어 보호한다.

### 공격 분기

- `POST /api/game/fleets`: `target: { type: 'monster', eventId }`를 추가로 받는다. 목적지 좌표와 `eventId`의 현재 위치가 같고 `ACTIVE`일 때만 허용한다(아니면 `409 TARGET_CHANGED`). 이동 시간 공식과 편성·예약 규칙은 기존과 동일하다. `FleetMovement`에 `targetMonsterEventId`를 추가한다.
- 도착 처리(`FleetService`의 공통 틱, 기존 5초 주기): 임무가 괴수 대상이면 한 트랜잭션에서 다음을 수행한다.
  1. 이벤트 문서를 읽고 `settleEvent`를 적용한다. 이벤트가 `ACTIVE`가 아니거나 위치가 목적지와 다르면 **표적 소실**: 전투 없이 `returnStartTime = now`로 귀환 전환하고 안내 문구를 남긴다.
  2. `MonsterBattleLog`로 중복 적용을 막는다.
  3. 괴수 방어 웨이브를 잔여 체력 상태로 만들어 `simulateBattle8Wave`를 실행한다(시드는 이동 ID, 기존 방식). 공격자 기술은 출발 행성의 연구, 방어 기술은 `typeSnapshot.techs`.
  4. 공격 함대 손실·생존 처리, 보고서 저장은 기존 로직을 그대로 쓴다. 약탈은 없다(괴수 자원 없음).
  5. 괴수 `state`와 `version`을 갱신하고 `MonsterContribution`을 upsert한다. 총 잔여 체력이 0이면 `DEFEATED`.
  6. 이벤트 문서 `version` 충돌이면 전체 트랜잭션을 재시도한다. 새 상태에 대한 결과가 달라질 수 있는 것은 정상이다.
- 도착 순서는 `arrivalTime`, `_id` 순으로 처리한다.

### 전투 엔진 확장

`CombatService.simulateWaves` 변경은 후방 호환을 유지한다.

- `defenderUnits` 옵션으로 `{ unitId: { stats, count, currentHull[] } }` 인라인 유닛을 받는다. 카탈로그 조회 대신 이 스탯을 쓴다.
- 반환값에 `defenderRemaining`(유닛별 잔여 체력 배열)과 `defenderHullDamage`(선체에 실제로 적용된 피해 합)를 추가한다. 피해 집계는 `executeFire`의 선체 적용 지점에서 `min(남은 체력, 선체 피해)`로 누적한다(과잉 피해와 실드가 막은 분량 제외). 기존 호출자의 반환 필드는 그대로다.
- 기존 사용자 간 전투 결과는 바뀌지 않아야 한다. 회귀 테스트로 기존 시드 결과를 고정한다.

### 보상 정산

- 처치 시 `DEFEATED` → `SETTLING`: 트랜잭션에서 참가자별 `rewardMicro = floor(poolMicro × damageEligible / Σ damageEligible)`를 계산해 `MonsterContribution`에 기록하고, 0보다 큰 금액마다 `CgcReward`(`kind: monster`, `rewardRef = monster:{eventId}:{userId}`)를 `PENDING`으로 만든다. 합계가 풀보다 작은 나머지(반올림 잔여)는 지급하지 않는다. 지갑 스냅샷은 정산 시점의 연결 주소를 쓴다.
- 보상 지급은 공용 outbox가 처리한다. 모든 `CgcReward`가 `COMPLETED`면 `SETTLED`. 예산 부족(`BUDGET_EXCEEDED`)이면 해당 건은 `PENDING`으로 두고 재시도 간격을 늘리며, 이벤트를 `BLOCKED`로 표시해 어드민이 알 수 있게 한다. 예산이 확보되면 자동으로 이어서 지급한다.
- `EXPIRED`(처치 실패)와 `CANCELLED`는 보상이 없다.
- 지급 수는 참가자 수와 같고 중계기가 순차 제출하므로 대규모 이벤트는 시간이 걸린다. 정산 진행률을 어드민에 표시한다.

### 어드민 UI(이벤트 탭)

- 괴수 종류 편집: 이름·설명, 유닛 목록(스탯, 웨이브), 기술, 모델 사양, 재생, 기본 풀. 서버 검증과 같은 규칙을 폼에 반영한다.
- **전투 시뮬레이터**: 선택한 괴수 종류에 대해 예시 함대 구성을 입력하면 영속 변경 없이 전투를 돌려 유효 피해와 손실 비용을 보여 준다(`POST /api/admin/monsters/simulate`). 보상 풀과 난이도를 정하는 도구다.
- 이벤트 생성: 종류, 기간, 풀(CGC), 이동 주기·거리. 풀이 현재 예산보다 크면 경고한다(차단하지 않음).
- 실행 현황: 위치, 잔여 체력 %, 상위 기여자, 정산 진행률, 예산 잔량. 조작: 이벤트 취소(보상 없음), 수동 재배치, `BLOCKED` 재개.
- 권한: 생성·수정은 `superadmin`, 조회는 `moderator` 이상. 모든 변경은 감사 로그.

### 사용자에게 보이는 것

- 성계도: 괴수가 있는 성계에서 해당 궤도에 괴수 표식(이름, 잔여 체력 %, 종료까지 시간)을 표시한다. `GET /api/game/galaxy`와 교통 조회에 `monsters` 필드를 추가한다. 괴수 유닛 상세는 노출하지 않는다.
- 출격: 전투 작전 지도에서 괴수를 선택해 드래그/클릭 출격한다. 기존 대기 함대 목록과 편성 예약을 그대로 쓴다.
- 보고서: 괴수 공격 보고서에 내 유효 피해, 누적 기여도 순위(내 비율), 괴수 잔여 체력을 표시한다.
- 알림: 소켓으로 등장·이동·처치 이벤트를 접속 중인 사용자에게 알린다. 정기 갱신은 기존 8초 주기를 따른다.
- 3D 모델: `hulls.js`에 괴수 형태 빌더를 추가하고 `MonsterType.model`로 지정한다. 모델 로드에 실패하면 정지 표식으로 대체한다.
- 모바일: 출격과 조회는 기존 모바일 컨트롤을 따르고 지갑 UI는 없다.
